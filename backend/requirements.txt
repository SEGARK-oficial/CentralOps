# Dependências DIRETAS do backend, pinadas em ``==`` nas mesmas versões do
# ``requirements.lock``.
#
# Por que pinado e não ``>=``: o CI e a imagem instalam ESTE arquivo, não o
# lock (ver .github/workflows/ci.yml). Com as diretas abertas, cada build
# resolvia o que estivesse publicado no dia — uma superfície de supply chain
# aberta, e uma mudança de API entrando sem ninguém escolher. Foi assim que o
# ``fastapi`` saltou de 0.136 para 0.14x e o gate de fronteira open-core cegou
# em silêncio (``include_router`` deixou de achatar ``app.routes``).
#
# Os ``>=`` que existiam aqui viraram comentário: o motivo de cada FLOOR (quase
# sempre um CVE) é a informação que não pode se perder na hora de subir versão.
# O pin nunca pode ficar ABAIXO do floor documentado.
#
# Como subir uma versão:
#   1. edite o pin aqui;
#   2. regenere o lock:  pip-compile requirements.txt -o requirements.lock
#   3. o teste ``tests/test_requirements_lock.py`` trava os dois alinhados.
#
# Nota: as ~50 dependências TRANSITIVAS ficam pinadas apenas no lock. Fechar
# isso por completo exige o CI instalar o ``requirements.lock``; ele não pode
# ser usado como ``-c`` porque tem extras (``uvicorn[standard]``) e o pip
# recusa: "Constraints cannot have extras".
